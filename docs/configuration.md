# Configuration guide

What each file in [`templates/`](../templates/) is for and what to change
when starting a project. `/python-rules:new` does all of this for you.

## Placeholders

| Placeholder | Replace with | Where |
|-------------|--------------|-------|
| `example-app` | Repo name: lowercase, hyphens | everywhere: pyproject, compose files, image name, README, workflows |
| `example_app` | The same in snake_case | `src/example_app/`, imports, pyproject, Dockerfile, compose files |
| `PROJECT` | Human-readable title | README, docs/overview.md, package docstring |
| year in `LICENSE` | Current year | LICENSE |

## Files

| File | Purpose | Change |
|------|---------|--------|
| `src/example_app/` | Example app: settings from the environment, an HTTP server with `/healthz`, a `main()` with `--version` and SIGTERM handling | Replace with the real app, keeping the conventions |
| `tests/` | pytest tests for each module (100% coverage) | Replace along with the app |
| `pyproject.toml` | Metadata, dependencies, ruff, mypy, pytest and coverage settings | Name, description, dependencies |
| `uv.lock` | Exact dependency versions | Regenerated by `uv lock`/`uv add` |
| `.python-version` | Python version for uv | With the Dockerfile and `requires-python` |
| `Dockerfile` | `dev` and `production` stages | Package and command names |
| `.dockerignore` | Keeps `.env`, `.git` and caches out of images | Nothing |
| `docker-compose.yaml` | Development: app from the working tree | Ports, added services |
| `docker-compose.test.yaml` | Tests | Added services (e.g. database) |
| `docker-compose.lint.yaml` | `lint` (pre-commit) and `secrets` (gitleaks history scan) | Nothing |
| `docker-compose.prod.yaml` | Production from the released image | Image name, ports, health check, added services |
| `.env.example` | Every environment variable with a comment and a dummy value, including PyPI's `UV_PUBLISH_TOKEN` | Add each new variable |
| `scripts/changelog-section.sh` | Prints a version's changelog notes; release check | Nothing |
| `scripts/bump-version.sh` | Next version from the latest tag; updates CHANGELOG, pyproject and uv.lock | Nothing |
| `scripts/check-env-example.py` | pre-commit check: `.env.example` lists every variable the app reads | Nothing |
| `scripts/check-env-secrets.py` | pre-commit check: no `.env` values in committed files | Nothing |
| `scripts/setup-github.sh` | Protects `main` and enables security features | Nothing; run once |
| `.github/workflows/ci.yaml` | Tests, package build with a pip install of the wheel, production image build | Add service containers if needed |
| `.github/workflows/lint.yaml` | Runs pre-commit and a gitleaks history scan | Nothing |
| `.github/workflows/release.yaml` | Actions-tab button (patch/minor/major) opens a release PR; merging it tags, pushes the image, attaches the sdist and wheel, optionally publishes to PyPI | Nothing |
| `.pre-commit-config.yaml` | ruff, mypy, uv-lock, yamllint, actionlint, shellcheck, hadolint, gitleaks, hygiene | Nothing |
| `renovate.json` | Keeps dependencies, lockfile, images, actions and hooks current | Nothing |
| `.yamllint.yaml` | yamllint rules | Nothing |
| `.gitleaks.toml` | gitleaks rules, exempting `.env.example` | Nothing |
| `.gitignore` | Venv, caches, build output, `.env` | Nothing |
| `README.md`, `CHANGELOG.md`, `docs/`, `AGENTS.md` | Skeletons in the required order | Fill in |
| `LICENSE` | MIT | Replace if the owner picks another license |
| `SECURITY.md` | How to report vulnerabilities privately | Nothing |
| `optional/postgres/` | How to add PostgreSQL (or SQLite) | Apply if needed, then delete `optional/` |

## One-time GitHub setup

- Run `scripts/setup-github.sh` (as a repo admin) right after the first
  push. It protects `main` (PRs only, squash merge, "CI passed" and "Lint"
  required), enables secret scanning with push protection, Dependabot
  alerts, private vulnerability reporting and CodeQL, and makes workflow
  tokens read-only. Re-running is safe.
- Install the [Renovate GitHub App](https://github.com/apps/renovate) on the
  repo. Without it `renovate.json` does nothing.
- After the first release, check the ghcr.io package's visibility (see
  [releasing.md](releasing.md)).
- Optional: publish to PyPI ([releasing.md](releasing.md#publishing-to-pypi-optional)).

## Local commands

```bash
cp .env.example .env
docker compose up --build
docker compose -f docker-compose.test.yaml run --rm test
docker compose -f docker-compose.lint.yaml run --rm lint
docker compose -f docker-compose.lint.yaml run --rm secrets
docker compose -f docker-compose.prod.yaml build
```

Or natively with [uv](https://docs.astral.sh/uv/): `uv sync`,
`uv run pytest`, `uv run mypy`, and `uvx pre-commit install` to lint on
every commit. Or with pip 25.1+: `python3 -m venv .venv`,
`.venv/bin/pip install -e . --group dev`, then `.venv/bin/pytest`.
